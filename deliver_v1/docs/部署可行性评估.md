# 真机与 ROS2 前置条件评估（E1 第 3 项 / E7–E12 的硬依赖）

> 评估日期：2026-09-23　评估机器：`3240704007`（Ubuntu 22.04 / kernel 5.15 / x86_64 / Python 3.10.12 / RTX 4090 D ×8，驱动 550.100）
> 对应大纲：§5 E1 第 3 项（ROS2 工作空间）、E6 Step 2 末（BPU 量化）、E7–E12

## 1. 结论（先说结果）

**真机链路当前有 3 个硬阻塞，且都不在本机内部能力范围内。**

| # | 阻塞 | 实测证据 | 影响范围 | 是否可自行解除 |
|---|---|---|---|---|
| 1 | **无 RDK-X3 硬件** | `lsusb` 无任何设备；无 `/dev/ttyUSB*`、无相关网卡 | E6 板载实测、E7、E10–E12 | ❌ 需硬件 |
| 2 | **无容器运行时** | `docker` / `podman` / `singularity` / `apptainer` / `nerdctl` **全部未安装** | 地平线 OE 为 Docker 分发 → E7 无法进行 | ⚠️ **可以**（本机 `uid=0`，可自行安装 docker） |
| 3 | **地平线工具链源不可达** | `developer.horizon.ai` 返回 **000（不可达）**；`hb_mapper` / `horizon_tc_ui` / `hrt_model_exec` 均不存在；PyPI 无对应包 | E7 的「算子覆盖率 / CPU 回退比例」 | ❌ 需换网络或离线安装包 |

**网络实测**：`pypi.org` → 200 ✓　`mirrors.aliyun.com` → 301 ✓　`developer.horizon.ai` → **000 ✗**

> **注意阻塞 2 与 3 的关系**：即便在本机装好 docker，**仍然拿不到地平线工具链镜像**
> （源不可达）。所以「装 docker」单独做不成事；必须**换到能访问地平线源的网络**，
> 或使用厂商提供的**离线安装包**。

## 2. 这对进度意味着什么

大纲把 E6 排在 W14–W16（约 2027-01），E7 在 W17–W18。
今天是 **W1 第 2 天**，所以时间上不紧张 —— 但这两个阻塞是**关键路径上唯一的硬依赖**，
且都不受「多写代码」影响。**建议现在就并行推进，而不是等到 W14**：

1. **确认能否拿到 RDK-X3 板子**（实验室现有？需采购？）—— 这决定 D 组是否可行
2. **确认一台能访问地平线源的机器**（校园网？厂商提供的虚拟机镜像？）
3. 在等待期间，把**不依赖硬件的那一半**做完（见下节的「可做的替代」）

## 3. 可以现在就做的替代方案（不假装等于板载实测）

| 大纲条目 | 板载要求 | 本机可做的部分 | **不能替代的部分（必须如实标注）** |
|---|---|---|---|
| E6 Step 2 末 | BPU 量化 | 已产出 ONNX 部署包（`export/deploy_4x1/`，含 operator census） | 算子覆盖率需地平线编译器 |
| **E7 精度损失** | 板载精度 | ✅ **可用 ONNX Runtime 做 INT8 PTQ**，测「相对 fp32 的成功率损失」 | ❌ BPU 算子覆盖率 / CPU 回退比例 / 真实延迟 |
| E7 延迟 | 板载 p50/p95 | 仅能在 4090 上给「相对加速比」 | ❌ 绝对延迟（跨硬件的绝对值无意义） |
| E8 缓存/异步 | 板载 | 可在仿真中做「chunk 长度 - 反应性」权衡（纯算法层面） | ❌ 网络抖动/丢包下的真实行为 |
| E9 部署形态 | 板载 | 仅能给出**设计对照表** | ❌ 功耗、续航、断网可用性 |
| E10/E11 真机 | 硬件 | E11 的**仿真版已完成**（`sim/follow.py` + `E11_跟随任务说明.md`） | ❌ 真机数据 |

> ⚠️ **纪律提醒（大纲 §2.2 已写）**：以上替代**只用于推进可做的部分**，
> **不得**把「ONNX Runtime 的 INT8 精度损失」写成「RDK-X3 上的部署结论」。
> IDAS 稿件被审稿人批评的正是「用理论估算冒充板载实测」，此处是同一条红线。

## 4. 建议的推进顺序

```
现在 ──┬─ ① 查明 RDK-X3 是否可得（实验室/采购）        ← 决定 D 组存亡，最优先
       ├─ ② 查明一台能访问地平线源的机器                ← 决定 E6/E7 能否收口
       ├─ ③ 用 ONNX Runtime 跑 INT8 PTQ，拿到「精度损失」← 本机可做，见 exp_plan.yaml E7-partial
       └─ ④ 补 E11 仿真版（已完成）                     ← 已交付
W14 前 ── ⑤ 板载环境就绪后：E6 板载实测 → E7 算子治理 → E8 缓存 → E9 形态对照
W22 后 ── ⑥ E10–E12 真机验证
```

## 5. 需要向导师/实验室确认的问题（逐条可直接拿去问）

1. **RDK-X3 开发板**：实验室是否已有？若无，采购周期多久？（这是 D 组的唯一硬依赖）
2. **地平线工具链**：学校/实验室网络能否访问 `developer.horizon.ai`？
   若不能，厂商是否提供离线安装包（OpenExplorer，需注明版本号，大纲 §5 E7 已强调）？
3. **ROS2 开发机**：真机侧用哪台机器跑 ROS2 Humble？是否已装好？
4. **真机场地**：校园内可用于 E10/E11 的室内场地（需能布置家具与行人干扰）
