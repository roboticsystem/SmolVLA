# P18 真机上板手册 —— hier_vla 分层混合部署

> 对应 exp_plan.yaml `P18-real`（已登记 2026-11-02）。
> 定位：**可行性验证**——验证「可见即规划，不可见即模型」的 hier 执行层
> 能否把真机闭环 SR 从纯模型的 0 抬起来。非统计显著性主线（n=15 只做描述性推断）。
> 上板前必读：`docs/已知问题与告警.md`（尤其 ①域差 ②最后15cm ⑧安全底线）。

---

## 0. 架构与数据流（一分钟版）

```
┌─ RDK X3 小车 ──────────────────────┐      ┌─ 笔电（GPU）──────────────┐
│ ros2_ws 五节点 (10Hz)：             │      │ infer_server --policy hier│
│  camera_node → /camera/image_raw   │ JPEG │  hier 仲裁状态机：          │
│  lidar_node  → /scan               │─────▶│   检出/记忆 → plan 模式     │
│  odom_node   → /odom               │ HTTP │    (LocalPlanner 绕障      │
│  vla_bridge ──┐                    │ POST │     + SweepDetDock 停靠)   │
│  control_node◀┘ /cmd_out ◀─────────│──────│   未检出 → search 模式      │
└────────────────────────────────────┘ 单步  │    (VLA chunk 兜底)        │
                                             └───────────────────────────┘
```

- 联动走 **HTTP**（不走 SSH）；SSH 只用来 rsync 同步文件和回拉日志。
- 服务端每次响应是**单步** `{"action":[v,w],"mode":...}`（无 `actions[]` 键，
  bridge 自动单步执行，仲裁可逐步打断）；search 层 VLA 前向产 10 步在服务端
  内部队列复用，只有队列空才真正跑前向。

## 2. §2 bearing/mirror 方向核验（上板第一步，必做）

**背景**：检测器输出的 bearing_deg 以「画面右半为正」；但激光索引按
「车头=0 逆时针（CCW）」约定。相机是否镜像安装（左右翻转）无法离线裁定，
由 `robot.yaml` 的 `camera.mirror` 开关决定：

- `mirror: true`（当前默认）→ bearing 直接当 CCW 角用；
- `mirror: false` → CCW 角 = −bearing。

**核验步骤**（5 分钟）：

1. 小车静止，把红盒目标放在**画面右半**（车头右前方），距离 1–1.5 m；
2. 启动 hier 服务 + bridge，发指令「去red的箱子旁边」；
3. 看 hier 日志 plan 模式的 w 方向：
   - **w < 0（右转，朝目标）** → `mirror: true` 正确，不动；
   - **w > 0（左转，转反了）** → 把 robot.yaml `camera.mirror` 改为 `false`，重启服务；
4. 再验一次左半画面（应左转 w > 0）。

**注意**：det_feat 特征路径保持 raw bearing（与训练数据一致），核验只影响
几何消费（激光/世界坐标/规划），改 mirror 不会破坏模型输入分布。

## 3. §3 HSV 标定复核（光照变了必做）

refs 是 2026-10-13 实测值。场地光照/白平衡与当天不一致就重标：

```bash
python3 tools/perception_smoke.py --camera 0 --measure
# 对准目标中心按 m 采样 HSV；把实测值写回 robot.yaml detection.refs
```

- 只标 **red / blue / yellow** 三色（P18 用到的色）；green/purple/orange
  仍是仿真占位值，**不得**加入 `use_colors`；
- 蓝色场景注意：蓝盒 S=113~142 vs 同色系货架 S≤80，靠 S 区分（robot.yaml
  已有 per-color 容差覆盖，别动）；
- 复核单目测距：`python3 tools/measure_distance.py --color red --distances 0.5,1.0,1.5,2.0`
  （工作带 0.8–2.0 m 误差应 ≤3.5%；<0.5 m 饱和属正常，见告警③）。

## 4. Bring-up 顺序（五个阶段，不跳步）

### 阶段 1：车侧硬件自检

```bash
python3 tools/selfcheck.py                 # 相机/激光/底盘串口
ros2 topic hz /camera/image_raw /scan /odom   # 三话题稳定出数
```

### 阶段 2：感知核验（§2 mirror + §3 HSV，都过了才继续）

### 阶段 3：笔电起 hier 服务

```bash
# 先 kill 旧实例（8000 端口可能挂着旧代码/旧模型的服务）
python -u server/infer_server.py \
    --project /home/d506/Desktop/3240704006/infer_bundle \
    --policy hier --detector real \
    --ckpt /home/d506/Desktop/3240704006/infer_bundle/deliver_v1/models/ft_real_v2 \
    --port 8000
```

确认日志三要素：`策略=hier`、`detector=real`（否则告警退化）、`设备=cuda`
（CPU 回落见故障排查 F7）。

### 阶段 4：车侧 ROS2 联调（**架空轮子！**）

```bash
cd ~/vla/ros2_ws && colcon build && source install/setup.bash
ros2 launch vla_nav nav.launch.py    # ⚠ 先改 launch 里的 server/instruction
```

架空发指令「去red的箱子旁边」，逐项核对：

- 目标在视野 → 日志 `mode=plan`，/cmd_out 的 (v,w) 朝目标收敛；
- 目标不在视野 → `mode=search`，慢速自转扫描（w_scan=1.15）；
- bridge 延迟：plan/search 队列步 rtt <100 ms；VLA 前向步 ~1.2 s 属正常
  （服务端队列复用，闭环平均请求频率 ~1 Hz）；
- 连续超时会进 `degraded`（v=0 原地慢转），网络恢复自动回正常——
  联调期看到 degraded 先查网，不是策略 bug。

### 阶段 5：着地试跑（P18-real 协议）

- **试次**：red / blue / yellow 各 5 试次，共 15 回合/轮；
- **摆位**：起点与朝向按场地固定标记摆放（保证试次间可比）；
- **指令**：训练词表句式「去{色}的箱子旁边」（L1 口径，别即兴改写）；
- **成功判据**：观察口径 = 激光表面距 ≤ 0.5 m 保持 2 s（正式口径 0.30 m
  对齐 robot.yaml navigation.success_standoff_m，**并行记录**两个数字）；
- **安全**：hier 参数不要现场调（仿真 E20 最优零调参起跑，跑完一轮按数据改）；
  急停 0.26 m（±28° 前向扇区）与底盘限速 0.203 m/s 已内置，
  但**首次着地手必须放在急停开关上**（告警⑧）。

## 5. hier 参数速查（robot.yaml `hier:` 段，勿现场调）

| 参数 | 值 | 含义 |
|---|---|---|
| v_cruise | 0.16 | 扫描巡航速度 (m/s) |
| w_scan | 1.15 | 扫描角速度 (rad/s) |
| k_ang | 2.2 | 航向比例增益 |
| stop_eps | 0.14 | 距离 ≤ 此值停住（表面距） |
| dock_dist | 0.8 | 末段速度斜坡区间起点 |
| max_dw | 0.55 | 角速度速率限幅（防抖） |
| emergency | 0.26 | 前向急停距离（±28° 扇区） |
| scan_arc | 1.5π | 转够此弧度未检出 → 前进换观测点 |
| relocate_steps | 25 | 换观测点持续步数 |
| mem_ttl | 25 | 世界坐标检测记忆 TTL（步） |
| dock_win | 0.9 | 表面距进入此范围 → 末段停靠 |
| dock_target | 0.25 | 停靠目标表面距（判据 0.30 内留余量） |
| dock_k | 0.8 | 末段速度比例 |
| align_tol_deg | 6.0 | 末段对准容差 |
| align_v | 0.08 | 末段对准速度 |
| align_max_steps | 12 | 对准限步（防无限原地转） |

底盘/执行约束：底盘 max 0.203 m/s（< 训练分布 0.35，保守降速）；
CK 协议串口为 mode 型（不支持弧线指令，control_node 已按此处理）。

## 6. 故障排查表

| # | 症状 | 原因 | 处置 |
|---|---|---|---|
| F1 | plan 模式转向反 | mirror 核验没做/装反 | §2 翻 `camera.mirror` |
| F2 | 检出率骤降 | 光照变了 HSV 失效 | §3 `--measure` 重标 |
| F3 | 全程 search 不进 plan | 目标色不在 use_colors / HSV 失效 / 链路没通 | 查 robot.yaml + curl 联通 |
| F4 | bridge 一直 degraded | 网络超时（>1s）或服务端挂了 | 看笔电服务日志；热点换网 |
| F5 | 服务日志无输出 | stdout 缓冲（print 未 flush） | 用 `python -u` 启动 |
| F6 | ckpt 找不到 | 相对路径按 server/ 目录解析 | 用绝对路径 |
| F7 | `设备=cpu` | 显存被占满 CUDA init 失败静默回落 | kill 大显存进程后重启服务 |
| F8 | 底盘不动 | control_node 串口 mode 型协议 / 急停触发 | 查激光 ±28° 是否有近障；看串口日志 |

| F10 | action 全歪/发散 | 双重归一化（bridge normalize_state 被开） | 保持 `normalize_state:=False`（默认） |

## 7. 一轮跑完后的决策点（对应 P18-real 登记条目）

- hier 执行层把 SR_real 从 0 抬起（任意试次成功）→ 可行性成立，记观察口径
  SR 与 plan 接管率，进入标定重测/跨场景泛化（P19）；
- 全 15 试次均未检出目标 → 先查 F2/F3（感知），感知 OK 仍不进 plan →
  归因域差下的检测-测距联合失效，记录后回仿真补域差消融，**不现场调参硬试**。
