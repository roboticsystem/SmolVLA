## 1. 创新点分解与研究假设

### 1.1 主创新 A：VLA 微调训练（PDRM）

> **第四版对齐（2026-10-21）**：子创新按**实际实验结论**重排。
> 原 A1/A2/A3 保留，但补上「已被实验证伪/证实的结论」，
> 并新增两个**证据最强**的子创新（A0 架构效应、A3b 记忆效应）。
> 成稿见 `docs/01_大纲与设计/E15_创新点成稿.md` §1。

| 编号 | 子创新 | 假设 | 实测结论 |
|---|---|---|---|
| **A0**（新增，证据最强） | **信息完备性原理 + 决策变量显式化**：把示范内部的「扫描↔追击」模式变量 \(z_t\) 作为额外输入通道交给模仿者 | 架构是主效应，而非示范数据 | ✅ **架构效应 +6.5 pp（p = 0.0067，n = 400 配对）**；示范条件化单独**不显著**（p = 0.215）；保留率 20–24% → **73–74%**（3.2 倍） |
| A1 | **动作空间重构**：把 SmolVLA 的机械臂动作头（6 维关节）改造为差速底盘 2 维连续动作 (v, ω) | 重构后模型可稳定收敛，控制频率满足实时要求 | ⚠️ **动作空间本身不是杠杆**：chunk 50→1 使开环误差改善 **4.9 倍**（0.0582→0.0119）而闭环**完全不变**（13.3%→13.3%）；「开环指标不具备选择能力」已写入论文 |
| **A3b**（新增，效应最大） | **跨帧时序记忆**：`perception.TargetMemory`（世界坐标累积 + 同色近邻合并 + 指数平滑 + TTL + 按当前位姿重算），特征档 `none`(4 维) / `mem`(8 维) | 补齐示范的跨帧能力可消除「一对多映射」 | ✅ **记忆效应 +7.75 pp**（比架构效应还大）；示范侧关掉记忆 SR **33.0% → 16.0%**（值 **17 pp**）；**用 1/3 数据即追平**；记忆效应**跨域保持**（§4.25） |
| A2 | **跨任务跨域迁移**：机械臂静态操作 → 移动跟随导航（MMD 域自适应 + 双映射） | 目标域演示数据量可减少 ≥ 60%，成功率损失 ≤ 3 pp | 🟡 域偏移下「记忆效应跨域保持」已验证；数据减少比例待补 |
| A3 | **场景化增强**：双分支注意力 + 单目深度辅助 + 空间约束因子 + 自适应图像增强 | 光照突变/遮挡场景下成功率达实用标准，恢复时间 ≤ 250 ms | 🟡 消融数据**已按当前代码重跑**（`export/e4_ablation.json`；旧表备份 `e4_ablation_20260924_old.json`，因 2026-10-20 场景光照改动而失效）：**自适应增强**在 `dim` 场景 11.7% → **84.4%**、`light_shift` 65.5% → 81.9%；**卡尔曼外推** `dim` 11.7% → 31.0%、`light_shift` 65.5% → 78.2%、`normal` 恢复时间 1242 → **297 ms**；「深度辅助」几乎无变化、「γ 空间约束」单独开**更差**（`normal` 79.9% < 82.5%）⇒ 需逐项如实报告；超参敏感性见 **E4b** |

> **共同前提**：A0 / A3b 的效果只在**「观测条件化示范 + 感知输入」**的配置下成立；
> 与特权示范搭配会**大幅劣化**（保留率 20–24%）⇒ 论文必须把「示范—模型信息集匹配」
> 作为方法的前提条件写进方法章首节，而不是当作实现细节。

### 1.2 主创新 B：轻量化端侧部署

| 编号 | 子创新 | 假设 |
|---|---|---|
| B0 | **推理图拆分与 KV cache 张量化**：把 SmolVLA 的「前缀图 + 去噪图」拆开，使视觉语言主干只前向一次，且 KV 以固定形状普通张量跨图传递 | **✅ 已实测验证**：三关数值校验 `max\|Δ\| = 0`（逐比特等价） |

| B1b | **步数 × 层数联合蒸馏**：flow-map/一致性蒸馏，同时压缩去噪步数与专家层数 | **✅ 已验证**（3 组种子）：**4 层 × 1 步**误差 **9.88% ± 0.31**、延迟 **11.3 ms**（**−93.1%，约 14.4× 加速**），且算子覆盖率 **94.1% / 91.6%** 越过 85% 判据 |

| B3 | **特征缓存 + 异步推理**：视觉特征复用、动作 chunk 复用、推理与控制解耦 | 端到端延迟 p95 ≤ 150 ms，控制频率 ≥ 10 Hz |

### 2.2 端侧算力预算（决定主创新 B 的可行性）

```
BPU 算力            = 5 TOPS (INT8)
目标控制频率         = 10 Hz
单帧算力预算         = 5 TOPS / 10 Hz        = 500 GOPS
工程安全系数         = 0.3（BPU 实际利用率）
→ 可用单帧预算       ≈ 150 GOPS
```

| 方案 | 参数量 | INT8 权重体积 | 是否可行 |
|---|---|---|---|
| SmolVLA 原模型直接端侧 | ~450M | ~450 MB | ✗ 超预算约 3 倍，且 LayerNorm/Attention 在 X3 上大量回退 CPU |
| 原始 + INT8 量化 | ~450M | ~450 MB | ✗ 仍超预算，内存亦紧张 |
| 裁剪 + 蒸馏 + INT8 | ≤ 30M | ≤ 30 MB | ✓ 目标方案（待 E6 实测验证） |
| 云边分层 | 端侧 ≤ 10M | ≤ 10 MB | ✓ 兜底方案 |

> **关键纪律**：以上为**预算估算**，不可直接写进论文当作结论。IDAS 稿件被审稿人批评的正是「部署数据全为峰值 TFLOPs 理论估算，无板载实测」。E6 必须给出**实测**延迟、功耗、温升，并以「理论 vs 实测」双栏呈现。

> **环境前置条件（已解决，详见 `E6_端侧可行性闸门实施手册.md` §1.4 与附录 A）**：
> ① **训练环境已建好**：`VLA/.venv_smolvla`（Python 3.12.8 + torch 2.10.0+cu128 + lerobot 0.6.2），`cuda.is_available() = True`。注意 **torch 必须锁 2.10.x**——lerobot 允许 `torch<2.12`，但 2.11 依赖 `nvidia-*-cu13` 需驱动 ≥ 580，本机驱动 550.100 只能跑 cu12。
> ② **prefix 与 KV 已实测**：prefix = **113 token**（视觉 65 + 语言 48），KV cache 仅 **2.2 MiB**（16 层 × `(1,5,113,64)`，bf16）。这意味着主创新 B 的 B0（KV 张量化）**开销可忽略、方案成立**。

## 3. 统一评测协议

### 3.1 四层指标体系

| 层级 | 指标 | 采集方式 |
|---|---|---|
| **感知与定位层**（E1b，🔴 第三版新增） | 位姿估计 **ATE / RPE**、平均/最大/**RMSE** 定位误差、**每 5 m 重定位**前后的误差跃变、**单目测距误差**（绝对/相对）、**导航结果对定位噪声的敏感度**（SR vs σ） | 真机闭环轨迹对照 + 仿真注入位姿噪声 |
| **训练层**（主创新 A） | 任务成功率、指令跟随准确率、动作预测误差（flow matching loss）、达到目标成功率所需演示条数、收敛步数、训练 GPU·h、未见指令/场景泛化准确率 | 训练日志 + 统一评测脚本 |
| **部署层**（主创新 B） | 参数量、模型体积、**BPU 算子覆盖率 / CPU 回退比例**、延迟 p50/p95、内存峰值、功耗、SoC 温升与降频、控制频率、**成功率保持率**（相对教师模型）、**四段能耗分解与续航预算**（E6b） | 板载埋点 + 外部功耗采样 |
| **任务层**（验证载体） | SR、SPL、NE、TL、TCR、跟随误差、丢失次数与恢复时间、画面抖动率、**路径几何质量**（ADO 安全裕度 / κmax / 总转角 / 最小通行间隙，E1c）、**人群拥挤度分层**下的跟随指标（E11b） | 自动判定脚本 + 人工复核 |

> **第三版新增说明**：原三层指标只有「任务量」，缺「**感知/定位精度**」与「**路径几何质量**」两类，
> 导致「画面抖动率」与「路径曲率」之间缺解释链条（参考论文1 §4.4 的 ADO / κmax 做法）。
> 「拥挤度」来自参考论文4 §2.1（半径内密度 + 意图权重），「能耗」来自参考论文3 第 1 章（三段拆解）。

### 3.2 统计规范

- 随机种子 **≥ 5 组**：42 / 123 / 456 / 789 / 1024
- 配对检验：paired bootstrap（10 000 次重采样），报告 **p 值 + 95% CI + 效应量**
- 多重比较：跨方法 × 跨数据比例 × 跨场景统一 **Holm 校正**
- 结果一律报告 **均值 ± 标准差**，且「绝对百分点 (pp)」与「相对百分比」并列
- 每个实验开跑前写入 `exp_plan.yaml`（变量、种子、判据），避免事后挑选

3. **层数裁剪是第二杠杆** —— 16→8 层降 51.0%，与去噪步数近似乘性叠加（可组合到 −88.5%）
4. **动作维度裁剪已证伪** —— `max_action_dim` 32→2 只省 0.010% 参数、延迟无改善；它属**正确性改造**（对齐 2 维差速底盘）而非优化手段，且截断有 29.55% 偏差，需微调
5. **联合蒸馏矩阵已完成**（5 配置 × 600 步，约 13 分钟）——详见 `E6_端侧可行性闸门实施手册.md` §2.8 ④b，可直接作为第 5 章主结果表：

| 配置 | 可训参数 | 误差（均值 ± SD，n=3） | 延迟 | 速度增益 |
|---|---|---|---|---|
| 16 × 1 | 99.85 M | 7.21% ± 0.32 | 32.9 ms | 80.1% |
| 12 × 2 | 75.29 M | **7.15% ± 0.09** | 37.3 ms | 77.2% |
| 8 × 2 | 50.73 M | 7.96% ± 0.01 | 26.0 ms | 84.1% |
| 8 × 1 | 50.73 M | 8.73% ± 0.06 | 18.6 ms | 88.5% |
| **4 × 1** | **26.17 M** | 9.88% ± 0.31 | **11.3 ms** | **93.1%** |

> 结论：**SD 仅 0.01–0.32 pp**，结果高度可复现；配对 bootstrap 显示跨配置差异均**统计显著**（95% CI 不含 0）。
> **4 层 × 1 步为性价比最优点**，相对教师约 **14.4× 加速**。
> 另注：12 层 × 2 步（37.3 ms）反而慢于 16 层 × 1 步（32.9 ms）——**减步数比减层数更省算力**，因为层数同时影响 prefill。

| 图 A 算子覆盖率 | 83.6% ✗ | **94.1% ✓** |
| 图 B 算子覆盖率 | 79.5% ✗ | **91.6% ✓** |
| 合计模型体积 | 774.5 MiB | **393.0 MiB**（−49%） |
| 端到端延迟 | ~162 ms | **11.2 ms**（−93.1%） |

> **裁剪同时解决了「延迟」与「算子兼容」两个问题** —— 这把 Route B 从「理论上可行」推进到「部署判据达标」。

### E6b 部署能耗与续航预算（W14–W16）· C 组 · 第三版新增

**目的**：把主创新 B 从「**延迟**」扩展到「**能量**」。
目前 §2.2 只算到算力预算（150 GOPS），没有换算成瓦/安培/续航——
而端侧机器人的真实约束是**电池（7.4 V / 3000 mAh）**，不是 TOPS。

**借鉴**：参考论文3 第 1 章的**三段式能耗拆解**（驱动行驶 / 差速转向 / 待机与辅助），
并采用其两个关键结论：
① 转向能耗随转角**超线性**增长（`|Δθ|^n`，n>1）——「两次 45° 的总能耗 < 一次 90°」；
② 存在 **U 型经济时速**（不是越快越省，存在最优经济速度）。

**降到本课题的四段分解**

| 段 | 内容 | 标定方式（**必须实测**） |
|---|---|---|
| 底盘驱动 | `F = (m₀+m_load)a + (m₀+m_load)gμ_r + ½ρC_dAv²`，`E = ∫F·v dt / η(v)` | 电机端电压电流采样 + 轮径/减速比已知 |
| 转向 | 与转角超线性、随负载放大 | 同上，对比不同转角序列 |
| **BPU 推理** | 单帧推理能耗（VLA 特有，量级随步数/层数变化） | 板载电流采样，区分空载与推理态 |
| 传感器待机 | RGB 相机 + D6 激光 + 通信 | 逐模块断电测静态功耗 |

**产出**：表 G9b-1（四段能耗分解）、表 G9b-2（理论 vs 实测，**含误差统计**）、
图 G9b-1（帧率-续航曲线：单帧推理功耗 → 可持续帧率 → 续航分钟数）。

**关键纪律**：参考论文3 的能耗模型是**纯理论、无实测标定、验证节只有数值仿真无误差统计**——
我方借鉴时**必须补实测标定与误差数字**，这既是学术规范要求，
也正好回应 IDAS 审稿意见对我方「只有理论估算无实测」的批评（**同一件事，反过来成为亮点**）。

**附带结论（可直接进第 5 章）**：把「U 型经济时速」与「转向超线性」两条结论，
转成对 VLA 动作输出的工程约束——动作平滑（少急转）与控制频率/推理步数的取值，
不只是平滑性偏好，而是**能耗最优性**问题。

## 7. 数据与标注方案

### 7.1 数据需求

| 数据 | 规模 | 用途 |
|---|---|---|
| 目标域演示轨迹（真机遥操作） | 3 场景 × ≥ 30 条（每条 2–5 min） | E2/E3/E4 微调 |
| 自建仿真回合 | ≥ 2 000 条 | 预训练与热启动、E3 源/目标域 |
| 语言指令标注 | 每段演示 ≥ 3 条同义改写 | 语言泛化评测 |
| 目标图像 | 每类目标 ≥ 10 张（不同视角） | E10 视觉导航 |
| 跟随场景记录 | 5 类干扰 × 10 次 | E11 |
| **拥挤度分层录制** | **3 密度档 × 3 遮挡档 × 10 次** | **E11b** |
| **定位标定采集** | **8 字/直线闭环各 3 次 + 5 个距离点测距** | **E1b** |
| **能耗标定采集** | **电机 / BPU / 传感器三路功耗采样** | **E6b** |
| 校准集 | 100 / 500 / 1000 帧三档 | E7 量化校准 |

### 7.2 关键约定

- **动作标签**：无线手柄遥操作采集，记录 2 维动作 (v, ω)
- **标签稀缺模拟**：按比例掩蔽**主损失与辅助损失的动作标签项**（不做数据丢弃），与 E5 一致
- **数据划分**：场景级划分（训练/测试场景不重叠），避免同场景泄漏
- **格式**：真机 `rosbag2` → 统一 HDF5（与 LeWM 数据格式对齐，便于复用既有管线）

## 8. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 端侧跑不通（闸门失败） | **高** | 主创新 B 崩塌 | E6 设置明确闸门；失败则转云边分层，并把「分层架构设计与实测」作为主贡献（兜底方案同样可发表） |
| 蒸馏后精度掉太多 | 中 | 成功率不达标 | 优先保精度、放宽体积目标；引入中间特征对齐；必要时端侧只跑动作专家、视觉塔留服务器 |
| RDK-X3 对 Transformer 算子支持差 | **高** | 延迟不可控 | E7 专门做回退治理；预判需要固定 shape、替换 LayerNorm/GELU |
| 真机演示数据不足 | 中 | 微调效果差 | 用仿真预训练 + 少样本适配；优先保证 3 场景 × 30 条的最低量 |
| 无 IMU 导致里程计漂移 | **高** | 长距离导航失败 | 扫描匹配定位 + 每 5 m 重定位；限制单回合长度；**E1b 量化定位误差并做 σ 敏感度**，避免「有对策无数据」 |
| 无深度相机导致测距不准 | 中 | E11 指标不可信 | E1 先标定单目测距误差，报告误差区间；以激光雷达为主 → **已升级为 E1b 的独立任务与判据** |
| **定位精度无数据，仿真结果不可外推** | **高** | E10/E11 的 SR/SPL 可信度受质疑 | **E1b**（ATE/RPE + σ 敏感度）；第 3 章补「位姿估计与误差预算」小节并写明是松耦合方案 |
| **仿真—实机差异无法归因** | 中 | 结论不可信 | **E12 误差预算**（已完成方法学闭环）；论文中把它作为**差异化立论**而非附录 |
| **能耗/续航只测不建模** | 中 | 主创新 B 缺「能量」维度 | **E6b** 四段能耗分解 + 实测标定；禁止只报理论估算（IDAS 审稿意见的同一条纪律） |
| **安全降级未定义** | 中 | 真机失控风险 | 第 3 章补「控制回路安全降级策略」：`vla_bridge` 超时/WiFi 断连 → 速度指令渐降 → 急停，并实测触发与恢复延迟 |
| 跨任务迁移增益不显著 | 中 | 主创新 A 减弱 | 转向「动作空间重构 + 场景化增强」作为主要贡献，诚实报告负结果 |
| 真机场地与安全 | 中 | 进度延误 | 使用校园室内场地；设置物理急停与限速阈值 |
